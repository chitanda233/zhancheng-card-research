先看一句话答案

Q / R 是六边形地图里的逻辑格坐标。它不是屏幕像素，也不是随机参数。你在报告里看到 (Q=3, R=-2)，首先应该理解成“地图上的某一个确定格子”。

《占城大师》当前已经确认：战斗地图模板保存格子的 Q/R 与邻接关系；稳定生成顺序会读取格子坐标；开格合法性判断在运行时读取目标格的 Neighbors。因此 Q/R 是地图逻辑结构的一部分，而不是单纯为了显示调试信息存在。

1 · 为什么六边形不用普通 X / Y 就完事

方格地图里，一个格子通常只有上、下、左、右四个主要邻居，x/y 很直观。六边形每格天然有 6 个邻居；如果硬套普通行列坐标，相邻关系会因为奇偶行或奇偶列产生额外分支。游戏和算法里因此常把六边形格写成 axial coordinate（轴向坐标）：用两个整数 q、r 描述一个格子，同时隐含第三个轴 s。

标准 axial / cube 关系是：

q + r + s = 0
s = -q - r

所以 (q=2, r=-1) 也可以看成三轴坐标 (q=2, r=-1, s=-1)。一般不需要把 s 单独存下来，因为它始终可以由 q、r 算出。

证据边界： 上述 q+r+s=0 是六边形轴向坐标的通用数学解释。当前项目证据已经确认 Q/R 与邻接用于地图逻辑，但本专题不把“标准 axial 的每个公式”冒充成已经反编译出的《占城大师》运行时实现。

2 · 一张图看懂 Q / R 与六个邻格

下面用标准 axial 坐标演示中心 (0,0) 周围的六个邻格。图只说明逻辑关系；客户端最终把地图朝哪个方向旋转、六边形是尖顶还是平顶，属于渲染映射问题，不影响“谁和谁相邻”。

在标准 axial 体系里，一个格子的六个邻居可以写成六组增量：

方向关系 Δq Δr 从 (0,0) 得到
邻格 A +1 0 (1,0)
邻格 B -1 0 (-1,0)
邻格 C 0 +1 (0,1)
邻格 D 0 -1 (0,-1)
邻格 E +1 -1 (1,-1)
邻格 F -1 +1 (-1,1)

再次强调：这是标准 axial 的概念模型。《占城大师》的关键运行逻辑已经直接保存或读取 Neighbors，因此分析具体某个格能不能开时，应优先相信实际邻接数据与运行时状态，而不是仅凭公式自行重建一份邻接表。

3 · Q / R 和屏幕上的 X / Y 不是一回事

这两套坐标解决的是不同问题：

坐标 回答的问题 典型用途
Q / R “这是地图上的哪个格？” 模板、邻接、寻路、范围、稳定生成顺序、规则判定
世界/屏幕 X / Y “它最终画在哪里？” Unity 世界位置、镜头、动画、点击命中、UI表现

因此同一个 (Q=3,R=-2)，在不同缩放、镜头、地图朝向甚至不同设备分辨率下，屏幕像素 X/Y 都可以不同；但它仍然是同一个逻辑格。反过来，也不要看到报告中的 Q/R 就把它理解成 Unity Transform 的位置。

4 · 标准六边形距离怎么算

如果采用标准 axial 数学，A=(q1,r1)、B=(q2,r2)，先算：

Δq = q2 - q1
Δr = r2 - r1
Δs = -(Δq + Δr)

最短格数距离为：

distance = (|Δq| + |Δr| + |Δs|) / 2

例如从 (0,0) 到 (2,-1)：

Δq = 2
Δr = -1
Δs = -1
distance = (2 + 1 + 1) / 2 = 2

意思是标准六边形网格中最少跨 2 个格子。

不要过度推断： 这个公式适合解释“六边形格距离”这个概念，但目前报告没有把它作为《占城大师》某个已确认战斗函数的行为结论。游戏可以在逻辑距离之外叠加桥、不可开启格、阵营、路线或模板限制。

5 · 在《占城大师》里，Q / R 具体参与了什么

5.1 地图模板：给每个格子一个稳定身份

BattleSetupConfig（战斗地图模板）提供地图骨架，其中包括格子 Q/R、邻接、双方主城、可开启状态以及预置内容。Q/R 因此首先是“这个 cell 是谁”的稳定定位方式。

5.2 初始化生成：坐标参与稳定生成顺序

BuildStableGenerationOrder 会把参与初始化的格子排成稳定处理顺序。现有逆向结论已经确认这一顺序与战斗 seed 和格子 Q/R 有关。它的意义是：在相同输入下，客户端能稳定复现逐格生成顺序。

这也解释了为什么“两个模板使用相同 seed”不一定得到同样结果：只要参与生成的坐标集合、固定格或模板结构不同，后续随机消费顺序就可能发生变化。

5.3 主城邻格：不是看画面近不近，而是看逻辑邻接

主城周围最多六个邻格会进入固定用途分配，例如金矿、一星、问号、防御、特殊士兵和普通格。这里真正重要的是模板/运行时认定的“邻格集合”，Q/R只是定位这些格子的逻辑身份。

5.4 特殊资源：会排除自己和邻格

特殊资源位置选中后，会把该格以及所有相邻格从候选池移除，从而避免两个特殊资源紧挨着。理解 Q/R 与六邻格后，这条规则会直观很多：系统不是按屏幕像素半径做一次模糊排除，而是在六边形地图拓扑里处理相邻关系。

5.5 开格：运行时直接看 Neighbors

GetHexOpenBlockReason 在基础状态检查后会调用 HasPlayerOpenAnchorNeighbor。该函数遍历目标格 Neighbors，读取 authoritative BattleHexCellState，检查邻格的阵营、是否已打开、是否主城等状态，判断目标格旁边有没有本方有效的“已开放锚点”。

因此：

Q/R 告诉你“目标是哪一格”
Neighbors 告诉你“它实际连着哪些格”
BattleHexCellState 告诉你“这些邻格此刻是什么状态”
三者合起来，才决定当前扩张关系

这比简单写“相邻坐标差 1 就能开”更准确。

6 · 为什么报告里有时只给 Q/R，不直接给“左上、右下”

“左上”“右下”依赖屏幕朝向与地图渲染方式。一旦地图旋转、镜像或切换六边形朝向，视觉方向词就可能变。Q/R 是更稳定的逻辑描述，所以技术报告会优先写坐标。

如果只是读玩法结论，不需要记坐标公式。看到 Q/R 时按下面三步理解即可：

  1. (q,r) = 某个确定的六边形逻辑格；
  2. 是否相邻，优先看实际 Neighbors / 模板邻接；
  3. 屏幕上的位置与视觉方向，是另一层渲染映射。

7 · 常见误读

误读 正确理解
Q/R 是屏幕 X/Y 不是；Q/R 是逻辑地图格坐标
Q/R 是随机数种子 不是；seed 与坐标可以共同参与稳定排序，但坐标本身不是 seed
q 或 r 相差 1 就一定相邻 不完整；标准 axial 需要同时看六种增量，项目分析还应以实际 Neighbors 为准
距离 2 就一定可以两步走过去 不一定；模板、桥、不可开启格、阵营和其他玩法状态都可能限制路径
新显现格的 Q/R 是显现时才生成 不是这个意思；Q/R 属于地图结构，显现/可开启是运行时状态
负数坐标表示地图外或非法 不是；轴向坐标天然可以出现负数

8 · 阅读其他专题时怎么用这页

在地块生成与兵种随机专题里，Q/R主要帮助理解模板固定格、稳定生成顺序、主城邻格与特殊资源排除；在局内战斗规则里，它帮助理解扩张边界和主城周围空间；匹配与卡牌专题通常不需要直接使用坐标。

后续如果恢复出《占城大师》明确的 Q/R → 世界坐标 变换、邻接构造函数或距离函数，本页会把“通用六边形数学”与“项目已确认实现”继续分栏维护，而不是混成同一个结论。
