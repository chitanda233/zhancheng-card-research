一页结论

理解这套系统最重要的一点，是把“地图生成”“地块显现”“玩家点击”分成三个阶段。当前代码证据更支持下面这条主线：

地图/模式确定地图骨架
→ 初始化所有参与生成的格子
→ 普通格先确定 25 / 50 / 100 / 250 价格档位
→ 再按该档位权重确定 R / SR / SSR / SSSR / 空
→ 再从合法候选中选择具体建筑
→ 把基础隐藏结果保存到格子状态
→ 玩家扩张后，附近格子进入可见/可开启状态
→ 玩家真正点击时读取已有隐藏结果
→ 少量点击阶段规则仍可能降级、升级或覆盖最终展示结果

因此，这页不再把“随机”当成一个动作。实际至少有三层随机：先随机地块档位，再随机稀有度，再随机具体候选。而玩家后来看到一个格子、点击一个格子，通常不是这三层随机第一次发生的时点。

层次 回答的问题 主要发生阶段
地图骨架 这局是哪张图、主城和固定格在哪里 对局建立时
地块档位 这个普通格是25、50、100还是250 初始化
内部稀有度 这个档位里抽到R/SR/SSR/SSSR还是空 初始化
具体建筑 同稀有度里最终是哪一个合法建筑候选 初始化为主
显现/可开启 这个格子什么时候出现在扩张边界、什么时候能点 对局进行中
最终展示结果 玩家点开后最后实际得到什么 点击时；通常沿用隐藏结果，但存在少量后置覆盖

这里还有一个明确的运行时例外：符合条件的未打开隐藏格在所有权变化时会进入“第二次生成”。这次不会重抽25/50/100/250价格档，而是保留原价格，按新归属方可用候选重新抽内部稀有度和具体隐藏内容；详见4.4。

如果只想知道机制本身，读第1～4节即可；第5节以后主要是加权、seed、地图池和证据细节。

1. 一个普通地块从出生到被玩家打开

1.1 初始化：先生成基础隐藏结果

BuildInitialSetupNormalized会规范化地图模板、双方牌组和主城，再由BuildStableGenerationOrder确定内部逐格处理顺序。普通格进入BuildCellContent后，主要按下面的顺序生成：

确定地块档位
→ 根据档位读取稀有度权重
→ 应用当局有效的稀有度修正
→ 抽出 R / SR / SSR / SSSR / 空
→ 从本局合法候选中选择具体建筑
→ 解析价格和内容
→ 保存到 BattleHexCellState

这里的“保存”很关键。当前主链不是等玩家以后点到这个格子时，才从零开始决定它是什么；多数普通格在初始化阶段已经有了基础档位和隐藏内容。

1.2 扩张显现：出现不等于重新随机

玩家打开边界格后，附近格子可能因为出现新的本方 opened anchor 而满足开放条件。GetHexOpenBlockReason除了读取目标格自己的CanOpen，还会调用HasPlayerOpenAnchorNeighbor检查Neighbors中的已开格、主城和阵营状态。

所以典型过程更接近：

开局时：B / C / D 已经有档位和隐藏内容
A 尚未打开：B / C / D 还不满足当前扩张条件
玩家打开 A
→ A 成为新的 opened anchor
→ B / C / D 满足邻接开放条件
→ UI开始显示这些格子的价格或可操作状态

这一步是“让已有格子进入视野/开放边界”，不是重新给B/C/D各掷一次25%。关于Q/R坐标和六邻格，可单独看Q/R六边形坐标概念专题。

1.3 玩家点击：通常读取隐藏结果，再做少量后置处理

玩家点击目标格的已确认主链为：

OpenHex（RVA 0x4534 / func[43532]）
→ GetHexOpenBlockReason（RVA 0x4597 / func[6642]）
→ SpendGold（RVA 0x4598 / func[43468]）
→ CommitOpenedHex（RVA 0x459B / func[25588]）
→ ResolveOpenedHexOutcome（RVA 0xF495 / func[25409]）

ResolveOpenedHexOutcome接收的是已经存在的BattleHexCellState。正常兵营路径优先通过SelectCardForCellArchitecture按格子保存的隐藏建筑去匹配卡牌；内容缺失或无法匹配时才走SelectCardForHex回退。当前开格主链里没有再次执行决定普通四档的Range(0,4)。

因此最准确的说法不是“开局已经完全锁死一切”，而是：开局已经生成基础隐藏结果；玩家点击时通常只是结算和揭晓，但少量明确规则仍可以改写最终结果。 如果一个仍未打开的隐藏格在点击前发生符合条件的所有权变化，它还可能先经过4.4所述的占领重生成，再由后续点击揭晓新的隐藏结果。

2. 随机到底随机了什么

2.1 第一层：普通格的25 / 50 / 100 / 250档位

没有被固定用途、模板内容或特殊资源提前占用的普通格，会在ResolveInitialRarity进入：

quality = Range(0,4)

四个整数等概率，因此普通格的第一层档位各25%：

Quality 玩家看到的地块 基础价格 进入普通档位随机后的概率
0 一星 50 25%
1 二星 100 25%
2 三星 250 25%
3 问号 25 25%

这四个25%只针对“真正走到普通档位随机”的格子，不代表整张地图最终一定有25%的25元格、25%的50元格。主城邻格、模板固定格、特殊资源、防御和金矿等都会提前改变整图构成。

2.2 第二层：档位决定内部R / SR / SSR / SSSR / 空权重

GlobalHexInfo给出四档基础权重：

地块档位 基础价格 R SR SSR SSSR 空
一星1001 50 74 20 5 1 0
二星1002 100 50 40 8 2 0
三星1003 250 0 0 90 10 0
问号1004 25 0 0 15 5 80

每行基础总权重是100，所以在没有额外修正时可以直接按百分比理解。例如：问号格首先有80%基础概率为空，剩余部分才是SSR 15%、SSSR 5%；三星格则不会从这张基础表抽R/SR，而是90% SSR、10% SSSR。

这里的R/SR/SSR/SSSR表示卡牌/建筑稀有度层级，不是卡牌自身的养成等级。玩家牌组里某张卡已经升到多少级，是另一套状态，不应和这一层随机混在一起。

这一步和第一层要分开看。比如“任意普通格最终进入问号且内部为SSSR”的基础概率，不考虑其他规则时是：

25%（先成为问号） × 5%（问号里抽SSSR） = 1.25%

2.3 第三层：同稀有度中再选具体建筑

确定内部稀有度后，ResolveRandomArchitecture会从合法候选中继续筛选：

  1. 稀有度必须匹配本次抽取结果；
  2. 问号格排除金矿和防御建筑；
  3. 金矿额度耗尽后排除随机金矿；
  4. 固定用途格只保留对应建筑类型；
  5. 候选规范化并排序；
  6. Range(0,candidates.Count)选择其中一项。

当前没有发现这一层给单张候选配置额外独立权重。如果有N个完全等价的合法候选，条件概率就是1/N。牌组缺失或为空时仍存在从战斗配置包回退的分支，因此不能把所有模式都写成“永远只从玩家装备牌组里抽”。

例如问号格已经抽到SSR，且当前有3个完全等价的合法SSR兵营，那么每个兵营在“已经是问号”的条件下基础概率约为15%÷3=5%；若从任意普通格开始算，还要再乘前一层的25%。

2.4 三层随机不要混成一句“翻格随机”

最容易产生误解的说法是“玩家翻一个格，系统随机一张卡”。当前证据更准确的模型是：

普通格初始化
  ├─ 第一层：随机价格档位
  ├─ 第二层：随机内部稀有度
  └─ 第三层：随机具体合法候选
          ↓
      保存隐藏结果
          ↓
玩家之后扩张到这里
          ↓
点击时结算 / 揭晓 / 少量覆盖

3. 不是所有格子都走这套普通三层随机

3.1 模板固定内容优先保留

主城、已打开格、不可开启格、已有ArchitectureId/CardId以及其他显式内容会优先保留。训练和教程也可以直接预置内容，因此这类格子会绕过普通随机的部分或全部步骤。

3.2 主城邻格是结构性配额，不是六个普通随机格

系统分别取得双方主城最多6个邻格，并各自执行一次ShuffleSix。洗牌决定用途落在哪里，而不是决定有没有这些用途。

槽位 用途 结果
0 GoldMine 强制金矿，按金矿价格
1 OneStar 强制一星，50
2 UnCharted 强制问号，25
3 Defense 强制防御候选，通常250
4 Soldier 只有SoldierPileHiddenHexEnabled开启时成立
5 None 继续走普通随机

地图边缘、固定内容或缺失邻位会使这套配额不能完整落地；双方独立洗牌也不保证镜像位置相同。

3.3 特殊资源会提前占用位置

竞技场至少为4时，初始化存在一次Range(0,101)并以结果小于30作为特殊资源事件入口，离散口径为30/101≈29.70%。命中后会从合法候选中选1或2个位置；每选一个位置，就从候选池移除它以及所有相邻格，因此两个特殊资源点不会紧挨着。成功构建特殊格后，该格不再进入普通档位和兵种随机。

TryBuildSpecialResourceCell在不同竞技场进入不同内容分支，但具体资源类型字符串所在共享跳板尚未完全恢复，因此这里只确认触发、数量和不相邻保护。

3.4 金矿来自多个来源，不能用一个“固定矿数”概括

一张图的初始金矿至少可能来自：模板预置、主城邻格强制金矿、普通R候选中的随机金矿。CreateGoldMineLimitState还能读取总额度和镜像侧额度，对“普通候选里的随机金矿”进行限制。

主城邻格的强制金矿可以绕过普通候选封锁，所以该额度不能直接理解成整张地图最终矿数硬上限。旧GlobalArenaInfoSheet2.minesCountLimit到当前BattleConfigPackage的完整注入关系尚未恢复，也不应把静态表值直接写成线上实测上限。

4. 点击时哪些结果仍可能变化

4.1 正常路径：沿用初始化隐藏结果

普通情况下，玩家点开格子后不会重新抽25/50/100/250，也不会从零重跑完整的“稀有度→具体卡牌”链。开格函数优先消费已经生成并保存的格子内容。

4.2 低价格子存在高品质重抽/降级路径

TryApplyFirstThreeCheapOpenReroll这条路径要求目标价格小于250、存在有效候选、已开低价格计数满足CountCheapOpenedHexesByPlayer<=3、候选稀有度至少为RareLevel 3，并排除部分资源和防御结果。命中后会尝试从R候选中重新选择，并排除金矿。

因此一个格子初始化时即使已经是SSR/SSSR，最终玩家点开时也可能被这一点击阶段规则改写。25、50、100属于低价范围，250不属于。函数名带“FirstThree”，但完整计数追加时序仍应以当前代码边界为准，因此这里不把它简化成玩家肉眼可直接数出的“严格前三次必降级”。

4.3 祝福、神器和引导也可能后置覆盖

  • 神器首次传说升级：满足对应开关、候选来自本局牌组、阵营有效且机会未消耗等条件时，可在已有候选基础上尝试替换为传说候选。
  • 超级召唤：SpendGold成功扣款后累计祝福进度；本地阈值为2000。达到阈值后进入Ready，之后在合法翻格结果处理中消费并尝试选择传说卡。
  • 教程/引导：教程可以预置结果；guidedGame的敌方SSSR还存在按当前档位降级的路径，另有龙骑士强制引导。
  • 被占领隐藏格：这不是点击阶段才发生的重抽，而是在符合条件的所有权变化时提前重生成隐藏内容；具体见4.4。

4.4 被占领隐藏格：价格档保留，内部稀有度与具体内容重抽

这里要先区分玩家视角的“占过以后又能点”和底层authoritative state。ShouldRegenerateCapturedHiddenHexContent会排除IsOpened=true、不可开启格、双方主城、桥格、资源箱、特殊士兵格，以及部分已有/特殊建筑。也就是说，这条机制不是把任意已经打开的敌方地块清空后再开一次；它处理的是所有权发生变化时，仍处于隐藏/未打开状态且允许重生成的captured hidden cell。

当前已经把调用时点追到所有权变化链：

ResolveHexOwnershipFromUnitPresence
→ ApplyHexOwnershipChangeIfNeeded（RVA 0x450B / func[43600]）
→ ShouldRegenerateCapturedHiddenHexContent
→ TryRegenerateCapturedHiddenHexContent（RVA 0xF368 / func[25323]）
→ 保留当前 Price，并由 Price 还原原品质档
→ GetCapturedHiddenHexAvailableRareMask(..., originalQualityRareMask)
→ 去掉新归属方没有合法候选的稀有度档
→ 按剩余权重重新抽内部稀有度
→ TrySelectCapturedHiddenHexCard
→ 写回新的隐藏内容状态
→ 玩家之后真正点击时再走正常 OpenHex 链揭晓 / 结算

第一层已经可以明确：不会重新执行普通格的Range(0,4)，25/50/100/250价格档位保留。 重生成函数直接从当前Price恢复原品质，因此同一坐标被捕获后仍然是原来的价格档：

保留的Price 还原档位 本档基础R SR SSR SSSR 空
25 问号 0 0 15 5 80
50 一星 74 20 5 1 0
100 二星 50 40 8 2 0
250 三星 0 0 90 10 0

第二层会重抽，但上表不能机械当成每次占领后的最终百分比。GetCapturedHiddenHexAvailableRareMask会把原品质允许的稀有度范围和新归属玩家当前真正存在的合法候选相交；某个稀有度没有候选时，该权重段不会继续参加这次选择，剩余有效权重按比例重新归一化。例如一个50金币一星格，若新归属方没有任何合法R候选，但SR、SSR、SSSR都存在，那么参与二次随机的权重从74:20:5:1变成20:5:1，对应条件概率约为76.92%、19.23%、3.85%。

问号格的“空”是本档结果之一，因此25金币格在占领后重生成时仍可能再次抽到空；它不是因为已经经历过一次争夺就必定变成建筑。

第三层也会重选具体内容。TrySelectCapturedHiddenHexCard使用新的playerId和当前合法候选上下文来构建被占领隐藏格候选，并存在Exact、ExactBarracksRestricted、BarracksFallback等候选/回退模式。因此这里不应理解为“把原来对手已经藏在这个坐标里的那张卡转交给新玩家”；更准确的是：价格档保留，但内部内容针对新归属方重新建立候选并重新选择。 同时，由于存在回退分支，也不能把所有模式简化为“永远只从玩家装备牌组中抽”。

这条重生成链没有重新进入开局的ResolveInitialRarity → ResolveUserLabelGoldCardOdd用户标签加权链。因此JustPaidUser、LosingStreak、InactiveUser、对手WinningStreak等开局SSSR增量，不会因为一个隐藏格发生所有权变化就在这里重新触发一次；占领重生成使用的是原价格档对应的基础稀有度权重，再叠加“当前哪些稀有度实际有合法候选”的可用性过滤。

最后要把“什么时候随机”和“什么时候揭晓”分开：二次随机发生在所有权变化时，第二次点击不是才开始随机。 新隐藏结果写回后，玩家以后真正点击该格，仍进入OpenHex → GetHexOpenBlockReason → SpendGold → CommitOpenedHex → ResolveOpenedHexOutcome。因此4.2和4.3列出的低价降级、超级召唤、神器、教程等点击阶段规则，仍可能在这份二次基础隐藏结果之上继续改写最终展示。

所以完整生命周期应写成：

开局生成：价格档 + 初始稀有度 + 初始具体内容
→ 格子保持未打开隐藏状态
→ 所有权变化
→ 若符合 captured hidden 重生成条件：
     保留价格档
     → 按新归属方候选可用性重抽内部稀有度
     → 重选具体隐藏内容
     → 保存新的隐藏结果
→ 玩家之后点击
→ 正常 OpenHex 结算 / 揭晓
→ 少量点击阶段规则仍可覆盖最终结果

因此，“开局已经生成整张地图的初始隐藏布局”与“部分未打开隐藏格在占领时进入第二次生成周期”可以同时成立。前者描述初始状态，后者描述运行时所有权变化；二者之间最关键的边界就是：第二次生成保留第一层价格档，只重做后面的内部内容层。

5. SSSR加权：这是第二层随机的修正，不是另一套地块生成规则

从系统结构看，这部分只是“内部稀有度抽取”的修正层。它不会把25元格改成250元格，也不会决定某格什么时候显现，因此放在普通生成主线之后理解更合适。

5.1 用户标签只增加SSSR权重

当前已恢复的用户标签增量为：

有效标签 加入本方SSSR段的权重
本方JustPaidUser，刚付费 10
本方LosingStreak，连败 50
本方InactiveUser，回流 30
对手WinningStreak，连胜 50

这些数字是权重增量，不是直接增加百分点。若当前这组增量合计为B：

P(SSSR) = (基础SSSR权重 + B) / (100 + B)
P(其他结果) = 原权重 / (100 + B)

例如一星格基础SSSR权重为1；若只存在连败+50，则这一格在加成尚未消费时的SSSR概率为51/150=34%，而不是1%+50%=51%。

5.2 这组用户标签是一次性消费资格

UserLabelGoldCardOddState按玩家维护共用消费状态。ResolveUserLabelGoldCardOdd在消费位已经成立后，不再返回JustPaid/LosingStreak/Inactive/对手WinningStreak这一组加成。当生成结果满足：用户标签加成仍大于0、最终稀有度为SSSR、且HexType属于兵营类时，该玩家消费位会被置为已消费；之后生成格回到不含这组用户标签的权重。

换句话说，它更像“提高本局稳定生成序列里第一个符合条件的SSSR兵营更早出现的机会”，而不是让整张地图每个格永久维持高SSSR率。消费的是本局生成器的加权资格，不等于清除账号上的连败、付费或回流标签。

没有在当前已恢复链路中发现“出一个SSSR后固定冷却N格”“连续N格不出就逐步加概率”“两个普通SSSR必须隔开”等规则。用户标签消费后，基础SSSR概率仍然存在，之后仍可能再生成SSSR。

账号标签如何触发、清除、扣次和进入匹配载荷，由匹配与机器人专题维护；本页只解释这些状态进入地块生成后如何影响内部稀有度。

每日祝福和周卡加成是在ResolveInitialRarity里的独立来源，不属于UserLabelGoldCardOddState这一消费位，也不能和上述用户标签机制混成同一个“保底”。

试算：权重增加，不是直接加百分点

6. seed、Q/R和“内部生成顺序”

BuildStableGenerationOrder把seed、Q坐标、R坐标和固定常数混合成64位排序键，再按键逐格生成。它不直接等于模板数组顺序，也不等于从主城向外的空间顺序，更不等于玩家点击顺序。

因此：

同一setupId + 同一seed + 同一双方牌组 + 同一战斗配置
≈ 可复现同一初始化结果

例如内部生成顺序可能是：

E → B → H → A → F → C → G → D

而玩家实际扩张顺序可能是：

A → F → C → D → B → H

如果某个一次性SSSR加权在内部第3个生成格H已经命中并被消费，玩家却第6次才扩张到H，那么主观体验会变成“第6次才出金”。反过来若玩家很早摸到H，又会感觉“第一下就出金”。所以玩家第几次看到SSSR，不能直接反推出生成器是第几次才随机到SSSR。

稳定生成顺序也不等于每格完全独立哈希决定全部结果。逐格生成仍会根据候选池、金矿额度、特殊用途等继续消费确定性随机数；前面某格的候选变化可能影响后续随机流。当前初始化链没有读取战斗秒数，时间流逝本身不会逐渐改变已经生成的档位。

Q/R本身只是六边形逻辑坐标，不是概率参数；详细概念见Q/R六边形坐标概念专题。

7. 可开启状态属于扩张规则，不属于随机品质

IsOpened 0x23 是否已打开

CanOpen不是“此刻已经出现在玩家边界”的同义词。GetHexOpenBlockReason还会调用HasPlayerOpenAnchorNeighbor(int playerId, BattleHexCellState target)遍历Neighbors，结合邻格的阵营、opened状态和主城状态判断目标格旁边是否存在有效开放锚点。

CommitOpenedHex提交后会进入ResolveOpenedHexOutcome，并可能触发相邻特殊奖励与MarkDynamicWallsDirtyAround刷新动态墙；BattleNavigationSystem.SetHexOpened则负责切换opened状态并标记后续刷新。这些属于开格后的状态和拓扑更新，不是普通品质重新随机。

10. 当前证据不能回答什么

  • 当前服务器针对具体账号实际下发的seed、地图选择、双方牌组、标签和模式开关。
  • 经典三形与多边形在普通竞技场入口的最终上游分流。
