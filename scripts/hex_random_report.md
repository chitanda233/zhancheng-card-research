# 《占城大师》地图与地块生成规则

研究日期：2026-09-08；2026-09-10 复核“新显现格子”和 SSSR 标签加权链。材料为2026-09-03本地资源快照，版本1.4.15.558-preview。结论来自本地WASM函数、恢复后的字段布局及配置表；未抓取当前线上对局载荷，不代表所有玩家、模式和服务器实验都启用了同一组开关。

## 先看答案

地图不是“玩家每点开一格，系统才临时把周围新格全部随机一次”。当前恢复出的主要决策链更接近：

```text
服务器或模式选地图模板
→ 保留模板中的固定格
→ 判定特殊资源位置
→ 给双方主城邻格分配固定用途
→ 对参与普通生成的格子建立稳定生成顺序
→ 普通格等概率抽地块档位
→ 按该档位的权重抽卡牌稀有度或空
→ 从该玩家本局牌组筛选具体建筑
→ 保存隐藏结果
→ 玩家扩张时周围格子进入可见/可开启状态
→ 玩家点击时读取既有隐藏结果，再执行少量重抽、引导和保底覆盖
```

阅读本页时必须把四类概念分开：

|概念|游戏中表示什么|可选结果|
|---|---|---|
|地块档位|玩家看到的外观与价格|一星50、二星100、三星250、问号25|
|卡牌稀有度|地块内部先抽中的候选级别|R、SR、SSR、SSSR、空|
|建筑结果|最终写进隐藏格的实际内容|具体兵营、金矿、防御、空或特殊资源|
|显现/可开启状态|这个格子什么时候被玩家看到、什么时候能点|属于局内扩张状态，不等同于重新生成档位和隐藏内容|

所以“这个格子什么时候出现在视野里”“为什么是250”“为什么里面是某个兵营”是三个不同问题。当前客户端代码证据支持：普通格的25%档位随机和内部稀有度随机主要发生在开局初始化生成链，而不是周围格子刚显现时再现场重抽一次。

## 1. 先选哪张地图

`BattleSetupConfig（战斗地图模板）`提供地图骨架：格子Q/R坐标、相邻关系、双方主城、可开启状态，以及模板预置的建筑或特殊内容。

|入口|具体选图规则|是不是随机|
|---|---|---|
|线上对局|`ApplyBattleCoreServerMapSelection`和`TryGetBattleCoreAuthoritativeMapSelection`可接收服务器给出的竞技场、地图类型、多边形ID和setupId|不一定；服务器可以直接指定|
|离线对局|有preferredSetupId时先精确匹配；否则按入口模式、竞技场、地图类型、多边形ID扫描并返回第一条完整匹配|该函数本身不是随机抽一张|
|训练局|使用training setupId和固定`hexConfigs`|固定编排|
|赛季PVP|同层候选`Weight`均为1000；首场另由`Pvp_PlayFirstMap=1001`固定矩形图|配置池等权，但仍可被入口或服务器指定|

普通竞技场在经典三形与多边形之间的上游最终分流仍未完整恢复。因此，配置中“存在某张地图”不等于当前线上一定按客户端自行随机选中它。

## 2. 开局时每个格子怎样确定

### 2.1 真实优先级

`BuildInitialSetupNormalized`和`BuildCellContent`按以下顺序处理。前面的规则命中后，后面的普通随机可能完全不执行。

|优先级|判断与动作|对最终格子的影响|
|---:|---|---|
|1|读取并规范化模板、双方牌组和主城|关键结构缺失会失败，不临时造图|
|2|保留主城、已开格、已有建筑及显式内容|模板固定结果不被普通随机覆盖|
|3|判定竞技场4以后的特殊资源事件|命中格直接走特殊内容|
|4|给双方主城邻格分别洗牌并分配六种用途|建立金矿、一星、问号、防御等结构性配额|
|5|对整组cells建立`BuildStableGenerationOrder`|决定开局初始化内部逐格处理顺序，不等于玩家点击顺序|
|6|其余普通格执行`Range(0,4)`|决定地块档位与基础价格|
|7|读取该档位的R/SR/SSR/SSSR/空权重|决定候选稀有度|
|8|叠加有效标签、祝福和周卡权重|只改内部稀有度，不重新抽地块档位|
|9|从本局牌组筛选并随机选择具体建筑|得到隐藏兵营、金矿、防御或空|
|10|解析价格并保存生成结果|之后玩家显现、点击时通常读取既有结果|

### 2.2 模板固定格先保留

主城、已打开格、不可开启格、已有ArchitectureId/CardId及其他显式内容不会进入普通格随机。教程预置和训练关固定内容也可以直接绕过后续档位与兵种抽取。

这意味着即使两个模板使用同一个seed，只要固定格或参与生成的坐标集合不同，后续随机序列也可能不同。

### 2.3 特殊资源位置先于普通品质

初始化先执行`Range(0,101)`；结果小于30，并且竞技场编号至少为4，才允许选择特殊资源格。代码离散口径为 **30/101≈29.70%**。

命中后：

- 从符合旧资源行条件且不是主城、已开格等状态的候选中选择；
- 本次生成1或2个特殊资源位置；
- 每选中一个位置，就从候选池删除它和所有相邻格；
- 因而两个特殊资源点不会紧挨着；
- 成功构建特殊格后直接返回，不再抽普通档位和兵种。

`TryBuildSpecialResourceCell`会按竞技场4、5、6及更高档进入不同内容分支。具体资源类型字符串所在共享跳板尚未完全恢复，因此这里只确认触发、数量和不相邻保护。

### 2.4 双方主城邻格有固定用途配额

系统分别取得两座主城的最多6个邻格，各执行一次`ShuffleSix`。洗牌决定用途落在哪个邻格，而不是决定有没有这些用途。

|洗牌槽|固定用途|地块档位或建筑结果|
|---:|---|---|
|0|GoldMine，金矿|强制选择金矿；最终按金矿价格|
|1|OneStar，一星|强制地块档位0，价格50|
|2|UnCharted，问号|强制地块档位3，价格25|
|3|Defense，防御|强制走防御建筑候选，价格通常250|
|4|Soldier，特殊士兵|仅`SoldierPileHiddenHexEnabled`开启时成立，否则退回普通用途|
|5|None，普通|继续执行普通四档随机|

标准六邻格完整且没有被预置内容占用时，玩家和敌方主城周围各会尝试安排一套上述用途。地图边缘、缺失邻位或固定内容可能使配额不能完整落地；双方独立洗牌也不保证镜像坐标一致。

### 2.5 剩余普通格才等概率抽地块档位：25%到底什么时候发生

没有固定用途的普通格在`ResolveInitialRarity`中执行：

```text
quality = Range(0,4)
```

四个整数等概率，因此这一层是各25%。随后档位直接映射到外观和基础价格：

|Quality|玩家看到的地块|基础价格|普通格第一层概率|
|---:|---|---:|---:|
|0|一星|50|25%|
|1|二星|100|25%|
|2|三星|250|25%|
|3|问号|25|25%|

这些25%只适用于走到普通档位随机的格子，不是整张地图的最终占比。主城邻格、金矿、防御、模板固定格和特殊资源都已在前面改变了构成。

更重要的是这25%的**发生时点**。复核`BuildInitialSetupNormalized`、`BuildStableGenerationOrder`、`BuildCellContent`和实际开格函数`25409`后，当前证据链是：初始化函数先拿整组`cells`建立稳定生成顺序，再按顺序逐格进入`BuildCellContent`；普通格在其中调用`ResolveInitialRarity → Range(0,4)`。而实际开格函数读取已经存在的`BattleHexCellState`，优先调用`SelectCardForCellArchitecture`取得预生成建筑对应的卡牌，并没有再次调用决定四档的`Range(0,4)`。

因此目前更准确的解释是：

```text
开局内部：A/B/C/D……普通格已经分别生成一星、二星、三星或问号
玩家打开某个边界格
→ 周围若干格进入可见/可开启状态
→ UI此时才把这些格子的档位展示给玩家
→ 但没有证据表明“显现这一刻”重新掷一次25%
```

例如内部生成结果已经是“B=三星、C=问号、D=一星”，玩家打开A后看到B/C/D同时出现，会产生“打开A后随机出了三个新地块”的体验；从当前初始化链看，更像是A的扩张动作把三个**已经生成过档位的格子揭晓出来**。

这里保留一个证据边界：负责“打开一个格后，哪些邻格被设为可见/可开启”的完整表现层/状态更新函数还没有完全恢复，因此不能把UI显现链的每一步写死。但就目前已恢复的初始化循环和`25409`开格处理而言，没有找到“邻格刚显现时再次执行`Range(0,4)`并重置档位”的调用链。

### 2.6 地块档位再决定内部稀有度：SSSR加权与一次性消费

`GlobalHexInfo（全局六边形地块信息）`给出四档基础权重：

|地块档位|基础价格|R|SR|SSR|SSSR|空|
|---|---:|---:|---:|---:|---:|---:|
|一星1001|50|74|20|5|1|0|
|二星1002|100|50|40|8|2|0|
|三星1003|250|0|0|90|10|0|
|问号1004|25|0|0|15|5|80|

每行基础总权重为100。没有动态修正时，权重可直接读作百分比。例如问号格先有80%为空；非空的20%中，SSR占15、SSSR占5。

用户标签只改这一层的SSSR权重，不改地块本身是一星、三星还是问号：

|有效标签|加入本方SSSR段的权重|
|---|---:|
|本方JustPaidUser，刚付费|10|
|本方LosingStreak，连败|50|
|本方InactiveUser，回流|30|
|对手WinningStreak，连胜|50|

这些数值是**权重增量，不是直接增加百分点**。付费、回流、连败可以共存；正常胜负更新链使同一玩家自己的连胜/连败互斥，但“对手WinningStreak +50”是读取对方标签，所以仍可与本方三项叠加。设当前尚未消费的用户标签增量合计为B：

```text
P(SSSR) = (基础SSSR权重+B) / (100+B)
P(其他结果) = 原权重 / (100+B)
```

不同加成状态下，单个进入该抽样层的格子临时概率如下。注意这张表只表示**用户标签加成尚未被消费时的这一格**，不是整局所有格子的固定概率：

|用户标签总增量B|一星 SSSR|二星 SSSR|三星 SSSR|问号 SSSR|
|---:|---:|---:|---:|---:|
|0|1.00%|2.00%|10.00%|5.00%|
|+10|10.00%|10.91%|18.18%|13.64%|
|+30|23.85%|24.62%|30.77%|26.92%|
|+50|34.00%|34.67%|40.00%|36.67%|
|+90（本方刚付费+连败+回流）|47.89%|48.42%|52.63%|50.00%|
|+140（再叠对手连胜）|58.75%|59.17%|62.50%|60.42%|

这也是为什么不能把“连败+50”理解成“之后每个格子永久都有三四成概率出SSSR”。代码里存在`UserLabelGoldCardOddState`这一局内消费状态，而且是**按玩家共用一个消费位**。`ResolveUserLabelGoldCardOdd`在该玩家消费位已经成立时不再返回这组用户标签加成；当实际生成结果满足以下条件时，单格生成链会把这个消费位设为1：

```text
当前玩家的用户标签加成仍 > 0
+ 本次最终稀有度为 RareLevel 4（SSSR）
+ 最终 HexType 属于 BarracksLike 兵营类
→ 标记该玩家 UserLabelGoldCardOddState 已消费
→ 后续生成格不再获得 JustPaid/LosingStreak/Inactive/对手WinningStreak 这一组用户标签加成
```

因此，如果玩家同时拥有“刚付费+连败+回流”，并且对手还处于连胜，这些加成不是四个彼此独立的“可各保一张金卡”计数；它们先合并成一次较大的B，首个符合条件的SSSR兵营生成后，**整组用户标签加成一起停止**。这只是清掉本局生成器里的消费资格，不等于清除账号上的连败、付费或回流标签；账号Buff仍按各自的对局结算规则持续或扣次。

这个“一次性消费”同样解释了为什么高增量不会把整张地图持续抬成极高SSSR率。它更像是：**提高本局稳定生成序列中首个符合条件SSSR兵营较早出现的机会**。如果前几个合格生成格没有命中，加成继续作用；一旦命中就停止。没有发现“固定每隔N格再触发一次+50”的规则。

同时也没有在当前已恢复链路中找到以下硬规则：

- “距离上一个SSSR至少N格”；
- “连续N格没出SSSR就逐步加概率”；
- “出一个SSSR后冷却N格”；
- “两个普通SSSR兵营禁止相邻”。

所以用户标签保护与“SSSR之间必须隔几块”是两回事。用户标签加成消费后，基础SSSR权重仍然存在，之后依然可能靠基础概率再生成SSSR；每日祝福和周卡加成也是在`ResolveInitialRarity`里单独加入的，不属于这个`UserLabelGoldCardOddState`消费位，不能把它们和用户标签的一次性消费混为一谈。

2026-09-10 对标签生命周期的补充确认：客户端连败/连胜刷新函数均以计数 `>4` 为触发条件，相反结果清零；刚付费 Buff 上限5、回流 Buff 上限2，结算动画结束链中存在扣次调用。回流 getter 使用“枚举存在或剩余 Buff>0”。完整的设置、清除、AI间隔和上传协议边界见[匹配与机器人专题](../matching/index.html)。这些静态函数仍不能证明服务端按付费/连败选择某个Bot。

每日祝福需`DailyBlessEnabled`和匹配的DailyBlessId；对应召唤属性转换后也加入SSSR段。周卡需要能解析WeeklyCycleCardType，且对应卡存在于本局Cards中，才增加1点。

### 2.7 从本局牌组确定具体兵营

确定R/SR/SSR/SSSR后，`ResolveRandomArchitecture`优先取得该格归属玩家的本局装备牌组，并依次过滤：

1. 稀有度必须与本次抽取结果一致；
2. 问号外观禁止随机金矿和防御建筑；
3. 金矿随机额度耗尽时排除金矿；
4. 其他固定用途只保留对应建筑类型；
5. 通过限制的候选规范化并排序；
6. 执行`Range(0,candidates.Count)`选择列表中的一项。

这一层没有发现单张卡独立权重。若有N个完全等价的合法候选，每项条件概率为1/N。牌组缺失或为空时，代码保留从战斗配置包回退的分支，不能把所有模式都简化成“只从玩家牌组抽”。

例如问号格有3个合法SSR兵营且没有额外修正，则每个兵营在该问号格中的基础概率为15%÷3=5%。如果从任意普通格开始计算，还要再乘先抽到问号档位的25%。

### 2.8 金矿数量与价格的具体规则

一张图的初始金矿由三部分构成：模板预置、双方主城邻格的强制金矿，以及普通R候选中随机选出的金矿。它不是地图模板里的一个固定总数。

`CreateGoldMineLimitState`可读取战斗包中的总额度和镜像侧额度：

- 未启用总额度时，不从随机候选中封锁金矿；
- 启用时，Remaining取`max(0,配置总额)`；
- 启用镜像侧额度时，每侧最多`floor(总额/2)`；若另有正的单侧值，再取两者较小值；
- 随机选中金矿后扣减对应额度；额度耗尽后把金矿从普通候选中排除；
- 主城邻位的强制金矿可绕过随机候选封锁，因此该额度不能直接当成最终矿数硬上限。

`GlobalArenaInfoSheet2`虽然还有`minesCountLimit`，但旧表到当前战斗包的完整注入链尚未恢复，不能把静态表值直接宣布为线上实测上限。

价格解析的优先级是：明确金矿先读取战斗经济配置，当前默认50；否则按地块档位取50/100/250/25；防御用途通常落到250；特殊空结果为25。价格主要由地块档位或固定用途决定，不是翻出兵营后再按兵种强弱估价。

### 2.9 seed和坐标决定稳定生成顺序：内部第几格不等于玩家第几翻

`BuildStableGenerationOrder`把seed、Q坐标、R坐标和固定常数混合成64位排序键，再按键逐格生成，不直接依赖模板数组的原始顺序，也不是按离主城远近或玩家点击顺序排列。

因此：

```text
同一setupId + 同一seed + 同一双方牌组 + 同一战斗配置
≈ 可复现同一初始化结果
```

例如地图空间上有A～H八个普通格，内部稳定生成顺序完全可能是：

```text
E → B → H → A → F → C → G → D
```

如果连败+50在E、B都没命中，在内部第3个生成格H命中了SSSR兵营，那么这一局用户标签加成此时已经被消费。玩家之后却可能按`A → F → C → D → B → H`的路径扩张，于是主观感受是“第6次才看到金卡”。反过来玩家若第一时间碰到H，又会感觉“第一下就出金”。因此，**玩家第几次翻到SSSR不能直接反推出标签加成在内部连续作用了多少格，也不能据此证明存在3格、5格之类的点击保底。**

还要注意，稳定生成顺序不等于每格完全独立哈希决定全部结果。逐格生成过程中会根据候选池、特殊用途、金矿额度等继续消费确定性随机数；若前面某格因候选变化少消费或多消费随机数，后面的结果也可能变化。当前初始化链没有读取战斗秒数；时间流逝本身不会逐渐修改已经生成的地块档位。

## 3. 玩家点击后哪些结果还会改

### 3.1 正常情况：新显现格通常是在揭晓开局生成结果

实际开格函数`25409`接收既有`BattleHexCellState`。正常兵营路径优先调用`SelectCardForCellArchitecture`，按格子已经保存的隐藏建筑匹配本方已拥有卡牌；内容缺失或无法匹配时，才进入`SelectCardForHex`回退。该开格函数中没有再次执行决定一星/二星/三星/问号的`Range(0,4)`。

因此当前代码证据支持把两件事分开：

```text
周围格子“新出现” = 扩张后进入可见/可开启状态
格子“第一次被随机生成档位和隐藏内容” = 主要在开局初始化链完成
```

也就是说，玩家看到“我翻开一块，旁边新冒出三块不同颜色/价格的格子”，不应自动解释成“这三块就在此刻各现场掷了一次25%”。当前证据更支持它们在开局已经有档位和隐藏内容，此刻只是被揭晓。负责邻格显现状态本身的完整函数仍待继续恢复，因此这里使用“当前证据支持”，不把尚未恢复的表现层细节写成绝对事实。

### 3.2 前几次低价翻格会压低高品质结果

`TryApplyFirstThreeCheapOpenReroll`要求：存在有效候选卡、地块Price<250、`CountCheapOpenedHexesByPlayer<=3`、候选RareLevel>=3、建筑可识别，且结果不是资源类或防御类。

命中后尝试从R卡池重新选择，并排除金矿。没有合法替换候选时不能保证降级成功。价格25、50、100属于低价范围，250不属于。计数函数遍历本方已开格并读取价格，不是按战斗秒数判断。

这意味着“开局生成了一个受标签加成命中的SSSR”也不保证玩家实际翻开时一定原样看到它：如果它落在符合前几次低价翻格重抽条件的位置，点击阶段仍可能把最终呈现改成R。标签加成的消费发生在初始化生成阶段，而低价重抽发生在玩家点击阶段，两者必须分开理解。

### 3.3 祝福、神器和引导属于后置覆盖

- 神器首次传说升级：在随机候选选出后，满足新神器开关、候选来自本局牌组、阵营有效且机会未消耗等条件时，读取attrType=3的锻造属性单独判定，成功后尝试替换为传说候选。
- 超级召唤：`SpendGold`成功扣款后累计相应祝福进度；本地阈值配置为2000。达到阈值后清零并设置Ready，之后在合法目标格的翻开结果处理中消耗并尝试选择传说卡。
- 教程覆盖：教程预置可以绕过普通生成；guidedGame的敌方SSSR会按当前地块档位降级，一星→R、二星→SR、三星→SSR、问号→空；另有龙骑士强制引导。
- 被占领隐藏格：存在重新生成路径，但会排除已开或不可开格、主城、桥、资源箱、特殊士兵格及特殊金卡建筑等对象。

所以准确说法是：多数普通格的档位和隐藏内容在开局确定，扩张阶段主要负责显现；真正点击时仍有少量明确的后置规则可以改写最终结果。

## 4. 保护与平衡机制汇总

|机制|发生阶段|具体保护|
|---|---|---|
|主城邻格六用途|开局|双方各自拥有金矿、一星、问号、防御等结构性机会，只随机落点|
|普通四档25%|开局初始化|参与普通生成的格子执行`Range(0,4)`；当前未发现邻格显现时再次重抽四档|
|特殊资源不相邻|开局|选择一个特殊资源点后删除它和相邻候选|
|金矿总额/分侧额度|开局|限制普通候选连续产生金矿，可按双方分配额度|
|问号隐藏限制|开局|禁止随机金矿和防御；基础80%为空|
|用户标签SSSR加成|开局逐格生成|刚付费+10、连败+50、回流+30、对手连胜+50，可累加为临时权重|
|用户标签共用一次消费位|开局逐格生成|首个符合条件的SSSR兵营生成后，该玩家后续格不再获得这组用户标签加成|
|引导局敌方SSSR降级|开局|避免新手引导中敌方获得过高档结果|
|低价前几翻重抽|点击|25/50/100价位的部分SSR及以上非资源非防御结果尝试换成R|
|祝福Ready状态|消费与点击|达到阈值只挂起一次，合法翻格时才消耗|
|seed与ContentHash|全程|同样输入可同步、回放并检测结果差异|

没有发现普通初始化按“战斗进行了多少秒”逐步调高或调低品质，也没有发现用户标签SSSR加成按固定格数周期重复触发。可变化的是服务器战斗包、seed、双方牌组、玩法开关、用户标签、累计消费和已翻格数量。

- 当前已读链路没有发现实时胜率、战斗秒数、固定N格SSSR冷却或固定N格递增保底，但这不等于能证明全游戏所有分包或服务端实验都不存在。
